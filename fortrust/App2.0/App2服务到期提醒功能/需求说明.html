2. 背景与目标

2.1 业务背景

孚创云监控为发电机组提供"物联网卡 + 云平台 + 运维服务"一体化解决方案。每台机组的"通信服务"、"历史数据存储"、"远程调参"、"固件 OTA 升级"等服务均有固定的服务期，到期后若未续期将产生以下影响：

  • 通信服务到期：机组离线，无法回传实时数据，用户失去监控权
  • 历史数据存储到期：新产生的数据无法归档，可能丢失
  • 远程调参到期：无法远程修改机组参数，需现场处理
  • 固件 OTA 升级到期：无法远程升级固件，安全补丁不能及时推送

当前痛点：服务到期前缺乏主动提醒机制，运维人员依赖人工台账或被动发现（机组掉线告警），导致服务中断后才发现，影响客户监控连续性，进而影响续约口碑。

2.2 功能目标

本次需求在 APP 内构建一套"主动到期提醒"机制，覆盖三个核心场景：

  1. 提前感知：用户打开 APP 时，系统级通知主动告知 30 天内即将到期的服务
  2. 集中管理：消息中心独立 Tab，按剩余时间倒序展示即将到期的服务清单
  3. 一键续期：详情页提供续期电话、实时监控入口，降低续期与监控切换成本

2.3 范围与边界

本期范围：仅做"到期提醒 + 续期入口"，不包含在线支付/在线续费流程。续期仍由人工电话沟通办理。
本期不涉及：Web 端同步、邮件提醒、短信提醒、企业微信/钉钉机器人通知（独立 PRD 规划中）。

3. 业务场景与用户故事

3.1 用户角色

角色关注点典型场景
运维主管 全部机组的整体服务健康度 每天打开 APP 第一件事是看消息中心，确认是否有即将到期的服务需要处理
驻场运维 所辖区域内机组的服务状态 收到系统通知后立即打开 APP 查看详情，联系续期

US-02 作为运维人员，我希望在消息中心集中查看所有即将到期的服务清单，以便批量跟进。

US-05 作为运维人员，我希望剩余时间根据紧急程度精确显示（天/小时/分钟），以便对即将中断的服务有直观判断。

4. 功能需求

4.1 系统通知机制 P0

4.1.1 触发条件

通知触发分两个通道，确保提醒到位：

通道触发时机行为
① APP 启动触发 用户每次打开 APP（冷启动 / 热启动进入前台） 前端调用 GET /api/services/expiring 获取列表，对每个即将到期服务发送本地通知
② 后台自动循环触发 P0 服务端定时任务调度（默认每 4 小时一次） 服务端主动向已开启通知权限的设备发送远程推送（APNs / FCM），无需 APP 在前台
  • 触发范围：剩余有效时间 > 0 且 ≤ 30 天 的服务
  • 文案模板：见 §4.1.2

4.1.2 通知文案规范

字段规则
标题 固定为「服务到期提醒」
正文模板 机组 {unitCode}（{stationName}）的 {serviceName} 将在 {remainText} 后到期，为避免数据通信中断和丢失，失去监控权，请及时续期。
变量说明 unitCode - 机组编号（例：G-08）
stationName - 电站名称（例：西藏那曲 2 号电站）
serviceName - 服务名称（例：通信服务）
remainText - 剩余时间文本（按 §5.4 规则生成）
示例（紧急） 机组 G-66（青海玉树电站）的通信服务将在 5 小时 23 分后到期，为避免数据通信中断和丢失，失去监控权，请及时续期。
示例（一般） 机组 G-15（新疆喀什光伏电站）的通信服务将在 13 天后到期，为避免数据通信中断和丢失，失去监控权，请及时续期。

4.1.3 通知样式

  • 形式：iOS / Android 系统横幅 + 通知中心条目
  • 应用图标：孚创云监控 Logo（蓝青渐变）
  • 优先级：剩余 ≤ 7 天显示为高优先级（横幅置顶 + 振动），8~30 天为普通优先级
  • 点击行为：点击通知 → 唤起 APP 并跳转服务到期详情页（参数 serviceId）
  • 循环来源标识：后台自动循环触发的通知，标题后增加"·循环提醒"角标（如「服务到期提醒 · 循环提醒」），便于用户区分

4.2 消息中心「服务到期」Tab P0

4.2.1 入口

  • APP 底部导航「消息」入口（次级 Tab 第 3 项）
  • 未读条数：Tab 角标显示当前用户可见的"30 天内即将到期项数"

4.2.2 Tab 结构

消息中心包含 4 个 Tab：「全部」「告警」「工单」「服务到期」。本期重点是「服务到期」Tab，其余 3 个 Tab 沿用既有实现。

4.2.3 顶部统计区

元素内容
左侧标签 + 警示图标 "30 天内即将到期"（橙色 ⚠ 图标）
右侧计数 数量 + "项"（例：5 项）
底部提示文案 "为避免数据通信中断和丢失，失去监控权，请及时续期"
+ 副文案"后台将自动循环推送提醒（默认每 4 小时）"

4.2.4 消息卡片设计

每条即将到期的服务显示为一张紧凑卡片，要求在不滚动的情况下，列表区尽量多展示。卡片信息层级：

信息位置样式
机组名称 + 电站名称 卡片头部左侧 粗体 13.5pt，"机组 G-08 · 西藏那曲 2 号电站"
剩余天数标签 卡片头部右侧 圆角 chip，≤ 7 天红色，"3 天后到期" / "5 小时 23 分后到期"；8~30 天橙色
运维服务：标签组 卡片中部 前缀灰色"运维服务：" + 多色圆角 chip（通信=蓝/存储=紫/调参=黄/OTA=绿）
到期 / 云猫 / 位置 卡片底部元数据行 10.5pt 灰字，键值对紧凑排列
立即续期 按钮 卡片右下角 蓝色胶囊按钮，≤ 7 天变红色，文案"立即续期 ＞"

4.2.5 卡片交互

  • 点击卡片：进入服务到期详情页（§4.3）
  • 点击「立即续期」按钮：进入服务到期详情页（同上）
  • 点击电话：详情页内才提供，列表页不展示

4.2.6 列表排序

按剩余时间升序（最紧急置顶），剩余相同时按机组编号升序。

4.2.7 空态 P1

当 30 天内无即将到期的服务时，Tab 无红点，列表区显示空态插画：✅ 图标 + "30 天内无即将到期的服务" + "所有机组服务状态正常"。

4.3 服务到期详情页 P0

4.3.1 页面入口

  • 点击系统通知 → 跳转详情页（带 serviceId 参数）
  • 消息中心卡片「立即续期」按钮 → 跳转详情页
  • 消息中心卡片本体 → 跳转详情页

4.3.2 页面结构（自上而下）

  1. Hero 区（渐变背景，紧急时红、警告时橙）
    • 警示徽章：「服务即将中断」

    • 剩余天数："距到期仅剩 X 天 / X 小时 X 分 / X 分钟"
    • 运维服务标签（彩色 chip 概览）
  2. 温馨提示（黄色背景，左边竖线）

    文案：「温馨提示：为避免数据通信中断和丢失，失去监控权，请提前办理续期。」

  3. 设备信息 section
    字段显示规则
    机组名称纯文本
    运行状态状态徽章（运行中/待机/离线） + 同行右侧"实时监控 ＞"链接（点击跳转监控页）
    所在位置"省份 城市 详细地址 海拔"

  4. 运维服务 section

    列出该服务项下所有受影响的子服务（彩色 chip）。

  5. 续期电话（蓝青渐变大卡片，整张可点击）

    • 主文案：「续期联系电话 · 点击拨打」
    • 号码：默认 400-888-0808（后台可配置）
    • 交互：点击调用 plus.device.dial()（原生）或 tel: Scheme 唤起系统拨号键盘

4.3.3 "实时监控 ＞" 链接规则 P0

  • 位置：固定在「运行状态」行的值区域，与状态徽章同一行，不独立成行
  • 样式：主色蓝色，前置细分隔线（视觉上与状态徽章分组）
  • 跳转目标：/pages/monitor/unit?unitCode={unitCode}
  • 不可用场景：机组当前已离线时，链接仍可点击（用户可看离线前最后数据），但文案加灰色"查看历史数据"

5. 业务规则

5.1 提醒触发规则

规则项规则内容
触发时机 APP 冷启动 / 热启动进入前台时
默认提前提醒时长 30 天（可在管理后台调整全局阈值，范围 7~90 天）
同一服务每天最多通知次数 1 次（按本地日期切换重置）
≤ 1 天时的通知频率 每小时最多 1 次（避免漏看关键时刻）
已到期后的处理 不再发到期提醒，转为"已中断"告警（由告警体系处理）

5.2 防骚扰策略

设计原则："重要但不打扰"。在最关键的窗口（≤ 7 天）保持高提醒密度，其他时段保持最低打扰。
剩余时间通知频率UI 样式
≤ 1 天 每小时最多 1 次 红色 Hero + 列表置顶 + 按钮变红 + 振动
2 ~ 7 天 每天最多 1 次 红色 Hero + 列表置顶 + 按钮变红 + 振动
8 ~ 30 天 每天最多 1 次 橙色 Hero + 卡片左侧橙条
> 30 天 不提醒 不出现在列表

5.3 优先级与排序

  • 列表排序：剩余时间升序，最紧急的置顶
  • 剩余相同时：按机组编号升序（G-08 在 G-15 前）
  • 卡片视觉权重：紧急（≤ 7 天）= 红边 + 红按钮；一般 = 橙边 + 蓝按钮

5.4 剩余时间显示规则

剩余时间显示文本示例
remain ≥ 1 天 {n} 天后到期 3 天后到期 / 29 天后到期
1 小时 ≤ remain < 1 天 {h} 小时{m} 分后到期 5 小时 23 分后到期
remain < 1 小时 且 remain > 0 {m} 分钟后到期 12 分钟后到期
remain ≤ 0 已到期 已到期（Hero 升级为红色"已中断"）

精度说明：后端存储使用 ISO-8601 时间戳，前端按本地时区计算并向上取整显示（"剩余 1.5 天" 显示为"2 天后到期"，避免误判）。

5.5 自动循环推送机制 P0

核心规则：剩余有效时间 ≤ 30 天的服务，由后端定时任务自动循环推送系统级通知，无需用户打开 APP，确保提醒到位。

5.5.1 Web 后台设置项（极简）

Web 后台「系统管理 → 提醒策略」页面（页面标题："运维服务到期提醒自动循环提醒策略"）仅提供 2 个设置项，对全部 6 类角色生效，不提供适用对象选择：

项规则
① 自动循环推送 开关 — 关闭后所有循环推送停止，仅在用户打开 APP 时检测；默认开启
② 循环提醒间隔 数字输入框（单位 h，支持小数，如 0.5 = 30 分钟）— 默认 4，范围 0.1 ~ 168（约 7 天）
生效范围 对全部 6 类角色（运维主管 / 驻场运维 / 项目负责人 / 设备管理员 / 设备操作员 / 设备资产所有者）生效
生效延迟 Web 后台保存后 ≤ 5 分钟生效（下一轮定时任务读取最新配置）
本期不提供：适用对象选择、触发规则（已处理免推/免打扰时段）、推送通道配置、推送统计图表、推送日志。这些在独立 PRD 规划中。

5.5.2 推送通道

  • iOS：APNs（Apple Push Notification service）
  • Android：FCM（Firebase Cloud Messaging） / 厂商通道（华为/小米/OPPO/vivo）
  • 推送凭据（device token）在 APP 首次启动时上报后端，后续由后端直推

5.5.3 推送触发逻辑

  1. 后端定时任务（cron: 0 */{period} * * *）每周期扫描一次
  2. 筛选条件：expireDate - now() ≤ 30 天 且 expireDate > now() 且 status = active
  3. 对每条服务，查找当前有权限接收的角色（6 类角色按数据权限过滤）+ 开启了通知权限的设备
  4. 通过 APNs / FCM 发送远程推送（无需 APP 在线）

5.5.4 与 APP 启动触发的协同

场景处理
用户打开 APP ① APP 启动触发 + ② 后台循环触发，两通道都工作，文案与样式一致
APP 被杀 / 后台运行 仅 ② 后台循环触发可生效（依赖系统推送通道）
用户禁用系统通知权限 两个通道均不发送，APP 内引导用户开启（一次性弹窗）

5.5.5 APP 端不展示循环配置入口

设计原则：为保持 APP 端界面简洁，不展示任何自动循环相关的视觉元素（卡片、详情页、设置页均不显示）。所有配置统一在 Web 后台完成。

用户在 APP 端的行为路径：

  • 看到系统通知（横幅 / 通知中心）→ 点击 → 跳转 APP 详情页
  • 在消息中心查看所有即将到期服务 → 点击卡片 / 立即续期 → 详情页
  • 详情页只关注"是什么服务、何时到期、怎么续期"——不涉及循环推送配置

需要调整循环策略的设备管理员：登录 Web 后台 → 系统管理 → 提醒策略（详见设计稿 simcard-expiry-app.html 中 Web 后台 Frame）。

6. 字段定义

6.1 卡片 / 详情 共享字段

字段类型必填说明
serviceIdLong是服务记录主键（详情页路由参数）
unitCodeString是机组编号，例：G-08
stationNameString是电站名称，例：西藏那曲 2 号电站
cloudCatCodeString是云猫设备编号，例：CM-2024-1872
serviceTypeEnum是服务类型枚举（见 §6.2）
serviceNameString是服务显示名，例：通信服务
expireDateISO-8601是到期时间（含时区），例：2026-08-31T23:59:59+08:00
remainSecondsLong是剩余秒数（后端计算，前端仅做展示）
remainTextString否后端预格式化好的剩余时间文本（前端也可自行格式化）
locationString是所在位置，例：那曲县 海拔 4500m
unitStatusEnum是机组运行状态：running / standby / offline

6.2 服务类型枚举 serviceType

枚举值显示名UI 颜色说明
communication 通信服务 蓝 SIM 卡 / 物联网卡，到期后机组离线
history_storage 历史数据存储服务 紫 云端数据归档，到期后新数据无法入库
remote_param 远程调参服务 黄 远程修改机组参数，到期后需现场调参
remote_diag 远程故障诊断与处理 青 远程诊断机组故障 + 协助处理，到期后仅能现场排查
maintain_mgmt 维保提醒与管理 粉 机组定期维保的计划、提醒、记录管理，到期后需手工管理维保台账

7. 接口约定

7.1 查询即将到期的服务列表

GET /api/services/expiring?days=30
Authorization: Bearer {token}

Query Params:
  days    Int  选填，默认 30，取值范围 7~90
  page    Int  选填，默认 1
  size    Int  选填，默认 20，最大 100

Response 200:
{
  "code": 0,
  "data": {
    "total": 5,
    "cycleHours": 4,           // 当前全局循环提醒周期（小时，支持小数），由后端从配置读取
    "items": [
      {
        "serviceId": 10231,
        "unitCode": "G-08",
        "stationName": "西藏那曲 2 号电站",
        "cloudCatCode": "CM-2024-1872",
        "serviceType": "communication",
        "serviceName": "通信服务",
        "expireDate": "2026-08-31T23:59:59+08:00",
        "remainSeconds": 259200,
        "remainText": "3 天后到期",
        "location": "那曲县 海拔 4500m",
        "unitStatus": "running"
      },
      ...
    ]
  }
}

Response 4xx/5xx:
{
  "code": 1001,
  "message": "服务暂时不可用，请稍后重试"
}

7.2 上报设备推送 Token（用于自动循环推送）P0

POST /api/devices/push-token
Authorization: Bearer {token}

Body:
{
  "clientType": "ios" | "android",
  "deviceToken": "a1b2c3d4e5f6...",     // APNs device token 或 FCM registration token
  "appVersion": "2.3.1",
  "osVersion": "17.4"
}

Response 200:
{ "code": 0, "data": { "registered": true } }

Notes:
  - APP 启动时调用一次（本地已有 token 可跳过）
  - 用户禁用系统通知权限时不下发循环推送
  - 服务端定期清理 90 天未活跃的 token

7.3 解除推送 Token（用户登出 / 卸载时调用）P0

DELETE /api/devices/push-token
Authorization: Bearer {token}

Query Params:
  deviceToken  String  必填

Response 200:
{ "code": 0 }

7.4 获取循环提醒配置 P2

GET /api/system/cycle-config
Authorization: Bearer {token}

Response 200:
{
  "code": 0,
  "data": {
    "enabled": true,            // 自动循环推送开关
    "cycleHours": 4,            // 当前循环间隔（小时，支持小数）
    "minHours": 0.1,            // 最小值（10 分钟）
    "maxHours": 168,            // 最大值（7 天）
    "configEditable": false     // APP 内只读，修改需到 Web 后台
  }
}

9. 异常与边界情况

编号场景处理策略
EX-01 接口返回失败 / 网络断开 APP 启动不阻塞，进入消息中心 Tab 时若 30 秒内无缓存数据，显示通用"加载失败，点击重试"占位；不发送通知
EX-02 用户禁用系统通知权限 进入消息中心时引导用户开启权限（一次性弹窗）；同时后台自动循环推送也将无法送达，需在引导文案中明确说明。用户拒绝后仍可在消息中心查看，不重复引导
EX-03 同一服务有多个即将到期子项 合并为一条消息记录，运维服务标签组内展示多个 chip（如 [通信服务][历史数据存储]）
EX-04 服务已到期但还在 30 天窗口内 剩余秒数 ≤ 0 时显示"已到期"红色标签，不再发到期通知，转交告警体系
EX-05 时区差异（用户在国外出差） 后端 expireDate 携带 +08:00 时区，前端按用户设备时区显示剩余时间，文案按本地化处理
EX-06 续期电话配置缺失 详情页电话卡片整张隐藏，不显示空态；不阻塞详情页其他功能
EX-07 用户角色无权查看某电站 接口层按数据权限过滤，前端不做特殊处理（拿不到就不会出现在列表）
EX-08 列表超过 100 条（极端电站群） 后端分页 size=20，前端上拉加载更多；列表头显示总数 + 当前已加载数

维度需求
性能 APP 启动调用接口耗时 P95 ≤ 800ms；本地通知生成 ≤ 100ms / 条；列表渲染 ≤ 200ms（100 条数据）
可用性 详情页离线缓存最近一次成功数据（LocalStorage，TTL 1 小时），无网时可看
兼容性 iOS 14+ / Android 8+（API 26+）
国际化 本期仅中文；文案统一从 i18n 资源读取，便于后续扩展
日志 通知发送失败、接口超时、跳转异常均需埋点上报，便于后续优化

11. 验收标准

11.1 功能验收

编号验收项通过标准
AC-01 系统通知触发 APP 启动时，对 30 天内即将到期的服务发送通知，文案符合 §4.1.2 模板
AC-02 消息中心 Tab 展示 Tab 名称"服务到期"，角标显示即将到期数，列表按剩余时间升序
AC-03 卡片信息完整性 每张卡片包含：机组 + 电站 + 剩余天数 + 运维服务 + 到期 + 云猫 + 位置 + 续期按钮
AC-04 卡片视觉紧急分级 ≤ 7 天卡片左红边、按钮变红；8~30 天左橙边、按钮蓝色
AC-05 详情页字段完整性 包含 Hero / 温馨提示 / 设备信息（含实时监控链接）/ 运维服务 / 续期电话全部模块
AC-06 "实时监控"链接位置 位于「运行状态」行值区域，与状态徽章同行，不独立成行
AC-07 续期电话唤起 点击电话卡片，唤起系统拨号键盘且号码预填正确
AC-08 通知点击跳转 从通知中心点击通知，能正确跳转到对应服务详情页（参数 serviceId 正确）
AC-09 防骚扰：日去重 同一服务同一天多次打开 APP，最多发 1 次通知
AC-10 防骚扰：≤ 1 天升级 剩余 ≤ 1 小时时，按小时频次发送（每整点最多 1 次）
AC-11 空态展示 30 天内无即将到期服务时，Tab 无红点，列表区显示空态插画
AC-12 权限引导 用户首次禁用通知后，消息中心进入时弹出引导弹窗，仅引导一次
AC-13 自动循环推送：Token 上报 APP 首次启动时调用 POST /api/devices/push-token，服务端成功注册设备 token（验证后端数据库有记录）
AC-14 自动循环推送：定时触发 当有剩余 ≤ 30 天的服务时，后台定时任务每 4 小时向有权限设备发送一次远程推送（iOS 验证 APNs、Android 验证 FCM/厂商通道均能收到）
AC-15 自动循环推送：周期配置生效 Web 后台调整循环周期（如改为 2h 或 6h），≤ 5 分钟内后续推送按新周期执行（验证：观察 1 小时内推送次数变化）
AC-16 自动循环推送：APP 不在线也能收到 APP 进程被杀死（模拟用户从最近任务划掉）后，远程推送仍能正常到达系统通知中心
AC-17 Web 后台设置页面（极简版） Web 后台「系统管理 → 提醒策略」页面（标题：运维服务到期提醒自动循环提醒策略）渲染正确：仅展示 "自动循环推送"开关 + "循环提醒间隔"数字输入框（支持小数，单位 h，范围 0.1~168，默认 4） 两个元素，不展示适用对象；保存配置 ≤ 5 分钟生效
AC-18 6 类角色数据隔离 同一台机组，授权范围内的角色能收到通知，未授权的角色收不到（按 6 类角色数据权限过滤）
AC-19 循环来源标识 后台自动循环触发的通知，标题后显示"·循环提醒"角标，与 APP 启动触发的通知可区分

11.2 视觉验收

  • 设计稿与实现偏差：颜色 / 间距 / 字号 / 圆角偏差 ≤ 2pt
  • 运维服务标签 5 种颜色编码（通信=蓝/存储=紫/调参=黄/诊断=青/维保=粉）严格一致
  • 紧急 vs 警告 视觉差异明显，无需文字说明即可一眼区分
  • APP 端不展示任何自动循环相关视觉元素（界面与文档描述一致）

11.3 性能验收

  • 列表 100 条数据渲染 ≤ 200ms（低端机如 OPPO A37 验证）
  • APP 启动到首屏可交互 ≤ 1.5s（含接口调用）
  • 通知点击到详情页可交互 ≤ 500ms
