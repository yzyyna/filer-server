📖 0. 名词术语

术语缩写定义
代币账户—系统中为用电方开立的虚拟账户，如 1 代币对应 1 NGN（汇算关系可配）
DVADedicated Virtual AccountPaystack 为每个用电方开立的专用虚拟账户，编号格式如 9930000123
锁机—通过 Modbus 协议下发参数使发电机组停止发电，限制其继续消耗代币
解机—反向操作，恢复发电机组运行
锁机阈值—触发"自动锁机确认单"的代币余额下限（账户余额 ≤ 阈值 → 锁机）
解机阈值—触发"自动解机确认单"的代币余额上限（账户余额 ≥ 阈值 且有机组锁定 → 解机）
汇算关系—代币 ↔ NGN（Paystack 入账用） / kWh ↔ 代币（电费计算用）双轨
Modbus—工业协议，云猫网关通过 Modbus 寄存器 7501/7504/7506/7502/7503 控制发电机组
二次确认—所有下发操作必须经过"操作员 → 系统校验 → 用户点确认"两道关，避免误操作
扣款密令—用电方支付时输入的密码，等同于银行支付密码，需两次输入一致校验
运维数据—锁机/解机执行后从设备回读的实时数据（功率、转速），用于操作回执验证

🎯 1. 项目背景

1.1 业务背景

发电方在非洲尼日利亚为用电方提供发电机组卖电服务。发电机组发电→用电方使用→按电量结算电费是核心商业模式。但当前痛点是：

  1. 资金流不闭环：发电量没有自动转化为"可回笼的代币"，电费靠人工催收，账期长、坏账高
  2. 风险控制薄弱：用电方余额不足仍可继续用电，导致坏账累积
  3. 三方协作低效：发电方对账工作量大、用电方支付体验差、平台方无统一审计

1.2 解决方案

电费交易结算管理系统承接以下业务诉求：

  • 资金流闭环：发电量 → 自动生成账单 → 用电方自动扣款
  • 风险实时控制：代币余额 ≤ 阈值自动锁机，断开发电
  • 三方协作标准化：发电方（发电+审核）/ 用电方（消费+支付）/ 平台方（账户+规则+审计）
  • 存量数据对接：发电量数据从已有 IoT 监控系统接入；代币账户对接 Paystack 充值通道

1.3 核心目标

视角目标
业务价值① 把"发电量"变现为"可回笼的代币" ② 用代币余额做风险控制 ③ 减少催收环节
发电方① 减少对账工作量 ② 异常账户自动锁机降低风险敞口 ③ 电量调整可追溯
用电方① 代币账户清晰 ② 一键支付 + 电量使用明细 ③ 跨周期账单可查
操作员① 锁机/解机操作标准化 ② 参数下发有回执验证 ③ 失败有重试机制

📌 2. 产品定位

2.1 价值主张

电费交易结算管理系统 = 代币账户（DVA）+ 锁机/解机 + 账单 + 支付 的一体化平台。

2.2 与现有系统关系

系统关系
发电机组物联网监控上游：发电量数据由此系统推送
云猫网关下游：锁机/解机指令通过 Modbus 协议下发到网关再到发电机组
Paystack第三方：代币账户的充值通道（专用虚拟账户 + Webhook 通知）

2.3 不做事项（v1.0 范围外）

  • ❌ 多币种汇算（v1.0 仅 NGN，单一代币）
  • ❌ 锁机分级（v1.0 单一动作，v2.0 考虑轻锁/重锁）
  • ❌ 部分支付（余额不足硬阻断，不支持挂账）
  • ❌ 跨月账单（v1.0 按规则周期内整月处理）
  • ❌ 电量预测（基于历史电量的预测性账单，v1.1）

🔄 4. 业务流程（8 张流程图详解）

详细流程图见 docs.html。以下为业务规则摘要。

4.1 业务流程图 · 账户创建

流程：系统管理员代用电方创建代币账户 → 4 步表单 → Paystack DVA 分配 → 启用

步骤输入输出
① 本系统账户信息用电方组织 + 账户名—
② Paystack 必填邮箱/名/姓/电话 + 银行—
③ 汇算关系1 代币 = ? NGN；1 kWh = ? 代币—
④ 扣款密令两次密令一致校验—
⑤ 启用（保存）—触发 Paystack POST /customer + /dedicated_account/assign
系统回调—返回 DVA 编号（如 9930000123 Wema Bank）
创建成功—跳转账户详情
  • 暂只支持开一个代币账户
  • DVA 编号由 Paystack 分配，本系统回填到账户
  • 启用=可扣款+可触发配置规则

4.2 业务流程图 · 账户结余

适用场景：用电方实时查看账户当前结余、充值扣款流水；管理员/发电方/操作员查看任一账户的实时余额

计算公式：账户结余 = ∑(RECHARGE 流水) - ∑(DEDUCT 流水)

关键不变量：Paystack 不返回账户余额（Paystack 只推送交易事件，不提供余额查询接口），本系统必须自己维护结余，严禁依赖 Paystack API 获取余额

流程：

  1. 用户进入账户详情页（page-token-detail）
  2. 前端请求 GET /token-account/{id}
  3. 后端按 account_id 查询 TokenTransaction 表，累加 RECHARGE 减 DEDUCT
  4. 返回当前结余 + 最近 20 条流水
  5. 实时更新（Paystack Webhook 触发充值流水写入后立即可见）

业务规则：

  • 结余显示精度：保留 2 位小数 + 代币单位（如 1,234.56 代币）
  • 结余为负数：触发红色告警（用电方欠费状态），但仍允许充值恢复
  • 并发一致性：写流水时加行级锁（SELECT FOR UPDATE）避免并发扣减导致结余错误
  • 历史流水永久保留

4.3 业务流程图 · 锁机（系统规则触发）

流程：系统自动检测账户余额 → 余额 ≤ 锁机阈值 → 生成锁机确认单 → 通知操作员 → 操作员处理 → 二次确认 → 下发参数 → 写锁机记录

触发条件：账户余额 ≤ 锁机阈值

关键节点：

  • 系统侧：检测账户余额 → 生成锁机确认单（LCK-2026-XXXX-XXXX）→ 通知操作员
  • 操作员侧：查看锁机确认单（待确认锁机列表）→ 点"处理 →" → 进入锁机操作页（from-confirm 模式）
  • 系统回显：账户 + 原因（账户只读、原因可改）
  • 操作员操作：选电站 → 选择机组（弹窗多选 + 电站回填）→ 读取/调整参数 → 点"执行锁机"
  • 二次确认弹窗：机组明细 + 实时功率/转数
  • 点"确认" → 按钮变"刷新" + 提示"⏳ 正在下发参数，请观察运行数据验证结果"
  • 系统执行：下发参数（Modbus 写入设备）→ 写入锁机记录
  • 操作员按"完成" → 跳转"锁机记录" tab → 完成 ✓

4.4 业务流程图 · 解机（系统规则触发）

流程：与锁机类似，但条件相反

触发条件：账户余额 ≥ 解机阈值 且 该账户下有机组处于锁定中

关键差异：

  • 操作员选择电站后，自动查询该电站下已锁定机组作为待选列表（不支持选择未锁定机组）
  • 解机阈值/锁机阈值动态显示（即同账户下，锁机阈值和解机阈值是两个独立配置）

4.5 业务流程图 · 手动新增锁机

流程：操作员主动发起锁机（不依赖系统规则触发）

适用场景：风险已显现但系统尚未生成确认单时（如已知客户即将违约）

入口：锁机确认页 → 点"+ 锁机"（new 模式）→ 进入锁机操作页

关键差异：

  • 无"账户回显"（操作员自由选账户）
  • 原因可填空
  • 选账户 + 选电站 + 选机组 + 读取/调整参数 → 二次确认 → 下发参数

4.6 业务流程图 · 手动新增解机

流程：操作员主动发起解机（不依赖系统规则触发）

适用场景：客户已付款但系统未及时触发解机时

入口：解机确认页 → 点"+ 解机"（new 模式）→ 进入解机操作页

关键差异：同手动锁机，但弹窗明细 + 实时功率/转数显示恢复前的低值

4.7 业务流程图 · 账单生成

流程：规则配置 → 自动触发 → 审核员审核 → 推送支付

角色步骤
系统调度定时器（每分钟定时查询一次）→ 查询账单生成规则（按电站 + 周期）
管理员规则配置：按周/按月/自定义 + 覆盖机组
系统采集覆盖机组的运行时长 + 电量 → 计算电费（电费 = kWh × 汇算）
系统生成账单（BILL-2026-W3-0007）→ 通知审核员
审核员待审核列表 → 点"审核 →"进入详情 → 审核（电量/电费/审核结论）→ 通过/拒绝（+备注）
系统更新账单状态（"已审核" / "已作废"）
推送通过 → 自动推送至"待支付账单列表"（无短信/站内信，系统菜单"账单审核"显示红色数字角标）
  • 同一电站同一周期仅一条有效规则（防重复生成）
  • 每分钟定时查询一次，匹配时间窗口则生成账单
  • 覆盖机组可指定具体哪些机组参与计算（默认 = 全部）

4.8 业务流程图 · 账单支付

流程：用电方选扣款账户 + 输入扣款密令 → 系统直接扣减代币余额 → 写扣款流水 + 更新账单状态

重要业务逻辑（v1.0 关键决策）：
  • ❌ 支付扣款不从 Paystack Transfer 走（Paystack 仅用于充值环节）
  • ✅ 支付扣款直接扣减本系统代币账户余额
  • Paystack → 用电方 DVA 充值 → 本系统收 Webhook → 增代币余额
  • 用电方 → 输入扣款密令 → 本系统扣减代币余额 → 写扣款流水
步骤用电方系统
1查看账单「待支付」列表—
2点"支付 →"进入支付确认页—
3检查账户余额（≥电费？）→ 否：余额不足请先充值—
4选择扣款账户 + 输入扣款密令—
5点"确认支付" → 提交扣款请求+密令扣款密令校验（两次密令一致？）
6—校验通过 → 写扣款流水 → 扣减代币余额
7—成功/失败模拟（90% 成功 / 10% 失败 demo）
8成功 → 跳转账单详情—

4.9 业务流程图 · 规则配置

📝 说明：v1.0 规则配置包含两类——账单生成规则（自动生成账单触发器）和解锁机确认规则（自动锁机/解机阈值规则）。

4.9.1 配置账单生成规则

需求：管理员配置"在何时、对哪些机组、按什么周期生成电费账单"的规则。系统按规则自动生成账单，无需人工干预。

核心字段：

  • 电站：规则作用电站（多选，单电站单条）
  • 周期：按周 / 按月 / 自定义（开始日+结束日）
  • 审核员：账单生成后通知的审核人员（多选主备）
  • 覆盖机组：本规则覆盖的具体机组（默认 = 全部）
  • 启用/停用：默认启用，可手动停用

业务流程：

  1. 管理员进入 page-rule-bill → 点"+ 新增规则"
  2. 填写规则表单（电站 + 周期 + 审核员 + 覆盖机组）
  3. 点"保存启用" → 写规则记录（RULE-2026-XXXX-XXXX）
  4. 系统按规则在 每分钟定时查询 时检查：周期到达 → 触发账单生成
  5. 采集覆盖机组电量 → 计算电费 → 生成账单 → 通知审核员

业务约束：

  • 同一电站同一周期仅一条有效规则（防重复生成）
  • 规则停用后，已生成但未审核的账单不受影响
  • 规则删除时需校验"无关联的待审核账单"

4.9.2 配置解锁机确认规则

需求：管理员配置"账户余额达到什么阈值时，自动生成锁机/解机确认单"的规则。系统按规则自动触发待确认锁机/解机确认单。

核心字段：

  • 账户：规则作用账户（v1.0 一个组织一个账户）
  • 锁机阈值（≤）：账户余额 ≤ 此值 → 触发锁机确认单
  • 解机阈值（≥）：账户余额 ≥ 此值且有机组锁定 → 触发解机确认单
  • 通知人：触发后通知的操作人员（多选）
  • 启用/停用：默认启用

业务流程：

  1. 管理员进入 page-rule-lock-unlock → 选择"锁机规则"或"解机规则" tab → 点"+ 新增规则"
  2. 填写规则表单（账户 + 阈值 + 通知人）
  3. 点"保存启用" → 写规则记录
  4. 系统按规则在 账户余额变更 时实时检查：余额进入触发区间 → 生成对应确认单
  5. 通知操作员 → 操作员处理 → 二次确认 → 下发参数

业务约束：

  • 解机阈值 必须 ≥ 锁机阈值 × 1.2（缓冲，避免频繁触发）
  • 解机规则仅在"该账户下有机组锁定中"时触发
  • 每个账户同一方向（锁机/解机）仅一条有效规则
  • 规则停用时，系统中已生成的待确认单仍按自动撤销逻辑处理（5.2 节）

⚙️ 5. 状态机

5.1 账单状态机（5 态 + 2 异常分支）

[待审核] ──审核通过──> [已审核(有效)] ──推送──> [待支付] ──支付成功──> [已支付] │ └─作废──> [已作废] ──重新生成──> [待审核]
状态含义可见方
待审核账单已生成，等待审核员审核审核员、发电方、管理员
已审核(有效)审核通过，自动推送至待支付账单列表审核员、发电方、管理员
待支付已推送给用电方，等待支付用电方
已支付用电方已扣款支付用电方、发电方、管理员
作废审核员作废（带原因，账单号作废重新生成）审核员、发电方、管理员

状态转换动作

  • 审核通过：POST /bill/{id}/approve（操作人/时间/原因三件套记录）
  • 推送：审核通过后无需短信和站内信，需在系统菜单"账单审核"处显示待审核的红色数字角标
  • 作废：POST /bill/{id}/reject（带原因，作废当前账单号，重新生成新号）

5.2 锁机/解机确认单状态机（4 态 + 2 失败分支 + 1 自动撤销分支）

[运行中] ──余额<阈值/手动──> [待确认锁机] ──操作员确认──> [锁定中] ──余额≥阈值──> [待确认解机] ──操作员确认──> [运行中] │ │ └─条件不满足(账户停用/规则停用/账户脱离触发区间)──> [自动撤销] └─条件不满足──> [自动撤销] │ └─参数下发失败──> [参数下发失败(需重试)]

自动撤销语义

  • 触发器：每 1 分钟由定时任务扫描"待确认"列表
  • 条件：校验每张确认单的关联账户/规则是否仍满足触发条件
  • 不满足条件的情况：账户被停用 / 规则被停用 / 账户被删除 / 账户余额已脱离触发区间
  • 动作：将该确认单状态置为 AUTO_REVOKE 并从"待确认"列表中移除
  • 审计日志：操作人=system，操作时间=扫描时刻，原因=具体不满足项
  • 与"作废"的区别：作废是审核员主动行为（删除原账单号重新生成），撤销是系统自动行为（条件不满足）；AUTO_REVOKE 不进入历史可查列表

6.3.5 确认单条件重检（关键业务规则）

⚠️ 重要：每次进入确认页面时，前端扫描以检查确认单是否有更新；后端服务是每分钟定时扫描所有 待确认锁机 + 待确认解机 列表，校验每张确认单的关联账户/规则是否仍满足触发条件。

校验条件：

  1. 关联账户是否仍存在
  2. 关联账户是否仍为"启用"状态（非停用）
  3. 关联规则是否仍为"启用"状态
  4. 账户余额是否仍处于触发区间

扫描时机（双端）：

  • 前端扫描：每次操作员进入"待确认锁机/待确认解机"列表页面时触发 → 调用 GET /lock-order/pending?since=last_visit → 仅返回新增/状态变更的确认单
  • 后端定时：每 1 分钟由 Spring Boot @Scheduled 任务全表扫描 → 不依赖前端访问

不满足时动作：

  1. 该确认单状态置为 AUTO_REVOKE
  2. 从"待确认"列表中移除（前端下次进入页面时通过 since 查询自动同步）
  3. 写入审计日志（操作人=system，操作时间=扫描时刻，原因=具体不满足项）
  4. 不进入"历史可查"列表

6.4 规则配置

6.4.1 账单生成规则

入口：管理员 → 规则配置 → page-rule-bill → 点"+ 新增规则"打开 modal-rule-bill

字段说明：

字段类型必填说明
电站下拉多选是本规则作用电站（来自运维系统）
周期下拉单选是按周 / 按月 / 自定义
周期配置动态条件必填按周：周几生成（1-7）；按月：每月几日（1-31）；自定义：开始日+结束日
审核员多选主备是账单生成后通知的审核人员（≥ 1 主 1 备）
覆盖机组多选否本规则覆盖的具体机组（默认 = 该电站全部机组）
启用/停用开关—默认启用；停用后定时任务跳过本规则

业务流程：

  1. 管理员填写规则表单 → 点"保存启用"
  2. 写 BillRule 记录（RULE-2026-XXXX-XXXX）
  3. 系统按 每分钟定时查询 检查：周期到达 + 规则启用 → 触发账单生成
  4. 采集覆盖机组的运行时长 + 电量 → 计算电费（电费 = kWh × 汇算）
  5. 生成 Bill 记录（BILL-2026-W3-0007）→ 状态：PENDING_REVIEW
  6. 通知审核员 → 审核员进入"待审核" tab 处理

业务约束：

  • 同一电站同一周期仅一条启用规则（防重复生成）
  • 规则停用后，已生成但未审核的账单不受影响
  • 规则删除时校验"无关联的待审核账单"，否则提示"请先处理待审核账单"
  • 自定义周期需不超过 31 天

关联页面：page-rule-bill（列表） / modal-rule-bill（配置弹窗）

6.4.2 锁机确认规则

入口：管理员 → 规则配置 → page-rule-lock-unlock → "锁机规则" tab → 点"+ 新增规则"打开 modal-rule-lock-unlock

字段说明：

字段类型必填说明
账户下拉单选是本规则作用的代币账户（v1.0 一个组织一个账户）
锁机阈值（≤）数字输入是单位：代币；账户余额 ≤ 此值 → 触发锁机确认单
通知人多选是触发锁机确认单后通知的操作人员（≥ 1 人）
启用/停用开关—默认启用

业务流程：

  1. 管理员填写规则表单 → 点"保存启用"
  2. 写 LockRule 记录
  3. 系统按 账户余额变更 时实时检查：账户余额 ≤ 锁机阈值 + 规则启用 → 生成锁机确认单（LCK-2026-XXXX-XXXX，状态 PENDING）
  4. 通知操作员 → 操作员进入"待确认锁机" tab 处理
  5. 操作员点"处理 →" → 进入锁机操作页（from-confirm 模式）
  6. 二次确认 → 下发参数 → 写锁机记录

业务约束：

  • 每个账户同一方向（锁机）仅一条启用规则
  • 锁机阈值必须 < 解机阈值 × 0.83（即锁机阈值 ≤ 解机阈值 ÷ 1.2，确保 1.2 倍缓冲）
  • 锁机阈值必须 > 0（避免零阈值导致永远触发）
  • 规则停用时，系统中已生成的待确认单仍按自动撤销逻辑处理（5.2 节）

关联页面：page-rule-lock-unlock / modal-rule-lock-unlock

6.4.3 解机确认规则

入口：管理员 → 规则配置 → page-rule-lock-unlock → "解机规则" tab → 点"+ 新增规则"打开 modal-rule-lock-unlock

字段说明：

字段类型必填说明
账户下拉单选是本规则作用的代币账户（v1.0 一个组织一个账户）
解机阈值（≥）数字输入是单位：代币；账户余额 ≥ 此值且有机组锁定 → 触发解机确认单
通知人多选是触发解机确认单后通知的操作人员（≥ 1 人）
启用/停用开关—默认启用

业务流程：

  1. 管理员填写规则表单 → 点"保存启用"
  2. 写 UnlockRule 记录
  3. 系统按 账户余额变更 时实时检查：账户余额 ≥ 解机阈值 + 该账户下有机组锁定 + 规则启用 → 生成解机确认单（UNL-2026-XXXX-XXXX，状态 PENDING）
  4. 通知操作员 → 操作员进入"待确认解机" tab 处理
  5. 操作员点"处理 →" → 进入解机操作页（from-confirm 模式）
  6. 二次确认 → 下发参数 → 写解机记录

业务约束：

  • 每个账户同一方向（解机）仅一条启用规则
  • 解机阈值必须 ≥ 锁机阈值 × 1.2（缓冲，避免频繁触发锁机/解机）
  • 解机规则仅在"该账户下有机组锁定中"时触发（避免无效触发）
  • 规则停用时，系统中已生成的待确认单仍按自动撤销逻辑处理（5.2 节）

关联页面：page-rule-lock-unlock / modal-rule-lock-unlock
